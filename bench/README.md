# Стенд замеров M0

Отвечает на три вопроса из плана: какое квантование Gemma 4 E2B брать по умолчанию, сколько ток/с реально на M1 8 ГБ и достаточно ли надёжны вызовы инструментов. Работает на чистом Node (>= 20), сборка не нужна. Запускать на целевой машине (MacBook Air M1 8 ГБ).

## Подготовка

```bash
bench/setup.sh        # ставит llama.cpp и ffmpeg через Homebrew, печатает версии
node bench/bench.mjs info    # проверяет, что под каждое квантование найден GGUF
```

Модели скачиваются при первом запуске сервера (до ~6 ГБ на все пять квантований). Репозитории с GGUF и список квантований лежат в `bench/config/candidates.json`; файл выбирается по списку файлов репозитория и передаётся явно (`-hff`), потому что `-hf repo:QUANT` молча берёт первый файл, если нужного нет. Любой запуск сверяет `model_path` из `/props` с ожидаемым файлом и помечает расхождение в отчёте.

## Порядок запуска

```bash
# 1. Скорость и надёжность по всем квантованиям (примерно 1-1,5 часа)
node bench/bench.mjs all

# 2. Спекулятивный декодинг на выбранном кванте (после шага 1)
node bench/bench.mjs speed --quants Q4_K_M --spec none,ngram-mod,ngram-simple,ngram-map-k --scenarios chat,edit

# 3. Режим «схема» (ответ ограничен JSON-схемой) и режим рассуждения
node bench/bench.mjs tools --quants Q4_K_M --mode both
node bench/bench.mjs tools --quants Q4_K_M --thinking

# 4. Мультимодальность: картинка, аудио (синтез через say), видео (ffmpeg)
node bench/bench.mjs media --quant Q4_K_M

# 5. Сравнение с MLX: поднимите сервер MLX отдельно и замерьте его эндпоинт теми же сценариями
node bench/bench.mjs speed --endpoint http://127.0.0.1:8802 --label mlx --model-name <id модели>

node bench/bench.mjs report   # собирает results/REPORT.md
```

## Что измеряется

| Команда | Метрика |
|---|---|
| `speed` | декод ток/с (чат и правка файла), префилл ток/с на 2K и 8K, время до первого токена холодное и с кэшем префикса, пик RSS процесса, изменение свопа, состояние троттлинга |
| `tools` | доля верных первых вызовов на 100 задачах (`bench/tasks/tasks.json`): чтение, поиск, shell, правка, запись, скиллы, отказ от вызова, второй шаг цикла по результату инструмента |
| `media` | проходят ли картинка, аудио и видео через llama-server, и сколько памяти занимает проектор |

Скорость берётся из `timings` llama-server, поэтому для спекулятивного режима это эффективная скорость. Один прогрев и 3 замера на сценарий, в отчёте медианы. Температура 0, чтобы запуски были сравнимы; если вывод со spec отличается от вывода без него, отчёт это покажет.

Правило выбора кванта из плана: самый лёгкий вариант, у которого успех вызовов инструментов не ниже эталона Q8_0 больше чем на 3 п.п. (`toolSuccessMarginPp` в конфиге). Его применяет `report`.

## Как читать цифры честно

- Корпус из 100 задач маленький: разница в 2-3 задачи это шум. Для близких квантов лучше прогнать `tools` дважды.
- MacBook Air не имеет вентилятора и троттлится. Если в отчёте стоит «троттлинг», дайте машине остыть и повторите.
- Не запускайте замеры рядом с браузером и IDE: память 8 ГБ, своп искажает всё.
- Задачи оценивают только первый вызов инструмента. Сквозное решение задач агентом проверяется позже (M2).

## Проверка самого стенда без модели

```bash
node --test bench/test/score.test.mjs
node bench/bench.mjs tools --bin bench/test/mock-llama-server.mjs --model-file /x/mock-Q4_0.gguf --quants Q4_0 --out /tmp/bench-mock
```

Заглушка отвечает правильно только на часть задач, это нормально.
