# M1: результаты оценки

Измерено на MacBook Air M1 8 ГБ, Gemma 4 E2B Q4_K_M, llama-server (контекст 16384, KV q8_0), ноутбук на батарее.
Набор: 30 задач на правку кода (edit30) и 20 на генерацию (gen20), скрытые тесты, один прогон на конфигурацию.

## Итоги

| Набор | native (база) | native + правила проекта | schema | loop (баг проверки) | loop | loop + ревью (баг проверки) |
|---|---|---|---|---|---|---|
| edit30 | 27/30 | 27/30 | 26/30 | 27/30 | 28/30 | 26/30 |
| gen20 | 3/20 | 14/20 | 4/20 | 15/20 | 15/20 | 14/20 |
| всего | 30/50 | 41/50 | 30/50 | 42/50 | 43/50 | 40/50 |

«Баг проверки» означает, что в loop проверка синтаксиса `node --check a b` смотрела только первый файл. В колонке «loop» проверка исправлена (eval/runner.ts, `SYNTAX_CHECK`), включён откат на schema при HTTP 500.

**Гейт M1 (20 из 30 на правку кода) пройден во всех конфигурациях, лучший результат 28/30.**

## Что показали прогоны

- Главный рычаг для генерации кода — строка с конвенциями проекта в системном промпте (ES-модули вместо CommonJS, node:test): 3 → 14 из 20. Без неё модель писала `require` в ESM-проектах.
- Schema-режим по качеству равен native, но в 4–5 раз медленнее. Поэтому он используется только как откат: когда сервер отвечает HTTP 500 «Failed to parse tool call arguments», шаг повторяется в schema-режиме (событие `fallback`).
- Loop с исправленной проверкой даёт +1–2 задачи и без регрессий. Реально сработал в двух задачах: add-stack-peek починилась со второй итерации, fix-moved-imports не помогло. Для задач без видимых тестов loop проверяет только синтаксис, поэтому логику (lru-cache, event-emitter, format-bytes, queue) и неполное переименование (rename-function) он не ловит.
- Самоконтроль (ревью своего диффа свежим контекстом): 50 раундов, 0 замечаний, 0 повторных заходов. Пользы нет, время на задачу выросло с 26 до 277 с. Прогон с исправленной проверкой остановлен на 35 из 50 по решению пользователя. Режим оставлен как опция, по умолчанию выключен; вернуться к нему стоит с более сильной моделью.
- Невалидных вызовов инструментов: 0,0% в прогонах с правилами проекта.

## Скорость и память

- 20–22 ток/с (19,6 в последнем прогоне). Цель 60 ток/с без спекулятивного декодирования недостижима: нужны ngram-spec и префиксный кэш (M4).
- llama-server занимает около 440 МБ RSS, но своп системы 10,5 из 11,3 ГБ (8 ГБ ОЗУ, много других приложений). Замера с зарядкой не было.
- Среднее время на задачу в loop: 33 с.

## Что не измерено

- Число срабатываний fallback на настоящем сервере: счётчик (`fallbacks` в JSON и строка в отчёте) добавлен после прогонов. По косвенным признакам (gen-csv перестал падать с `doneReason=error`) откат работает.
- Одиночные прогоны: разброс между запусками не оценивался, разница в 1–2 задачи в пределах шума.
- Скорость на зарядке, спекулятивное декодирование, изображения/аудио.

## Остающиеся провалы

gen-lru-cache, gen-event-emitter, gen-format-bytes, gen-queue (неверная логика, синтаксис корректен), rename-function (не все вхождения), fix-moved-imports.
