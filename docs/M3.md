# M3: встроенные модули

Объём по плану: браузер через CDP, предпросмотр, статистика проекта. Видео-вложения **отменены** по решению пользователя (модели E2B с видео работают плохо, а нужда в них небольшая): в приложении видео не прикрепляется, при попытке окно прямо говорит об этом.

Гейт M3: агент проходит сценарий «открой страницу, проверь, исправь». Он покрыт сквозным тестом окна (модель подменена сценарием) и проверкой с настоящей Gemma 4 E2B на Mac (`apps/desktop/scripts/m3-real.ts`), результаты и разбор сбоев в разделе «Проверка на Mac» ниже.

## Правки, перенесённые из M2

- E2B не вызывала `read_file` и просила прислать файл. Теперь системный промпт прямо говорит: файлов не видишь, читай инструментом, пользователя не проси. Если на просьбу о правке модель ответила «пришлите файл» и не вызвала ни одного инструмента, цикл один раз за ход подталкивает её сообщением и событием `nudge` (в ленте и в CLI видно «подсказка модели»). Тесты: `agent.test.ts` (три на nudge).
- Проверка на Mac показала ещё одну слабость E2B: после `read_file` она иногда зовёт `edit_file` без `path` (три невалидные попытки подряд и обрыв хода). Теперь, если в этом ходе файл уже читали, а `path` опущен, цикл подставляет прочитанный файл (если `old_string` там не найдётся, инструмент отвечает обычной ошибкой). В описании инструмента `browser` добавлено: снимок — это отрисованная страница, а не исходник, перед правкой файла его надо прочитать. Тест: `agent.test.ts`.
- В `docs/M2.md` исправлено число тестов, `apps/desktop/scripts/e2e.ts` теперь ищет Chromium через `CHROME_PATH` или Playwright.

## Браузер

Агент получает инструмент `browser` с действиями `open`, `snapshot`, `click`, `type`, `press`, `scroll`, `back`, `reload`, `console`, `screenshot`, `wait`. Страница показывается модели не картинкой, а текстовым снимком: интерактивные элементы пронумерованы (`[3] button "Greet"`), действия адресуются номером. Снимок обрезается до 4500 символов, продолжение берётся со сдвигом. Консоль страницы (ошибки, `console.log`) читается действием `console`. Скриншот уходит модели картинкой, если подключён mmproj, иначе инструмент отвечает текстом.

Устройство (`packages/core/src/browser`):

- `PageHandle`/`PageFactory`: страница это CDP-сессия. `ChromeFactory` запускает отдельный headless Chrome/Chromium (CLI, режим разработки, тесты; путь ищется сам или из `CHROME_PATH`/`browser.executablePath` в конфиге). В приложении страницы создаёт главный процесс Electron: скрытые окна с отдельным профилем без прав на камеру, уведомления и скачивания, управляются они по `webContents.debugger`; команды идут по `platform`/`platformReply` из utility-процесса.
- `BrowserController`: вкладки, снимок, действия, буфер консоли, скриншот, трансляция кадров в окно (`Page.startScreencast`), ввод пользователя.
- В окне вкладка «Браузер»: адресная строка, вкладки, назад/вперёд/обновить, кадры страницы, клики и клавиши пользователя доходят до страницы (пользователь может перехватить управление, а агент увидит результат в следующем снимке). Когда агент открывает страницу, вкладка показывается сама.

### Права

Новый класс риска `browser`.

| Что | Правило |
|---|---|
| `open` локального адреса (`localhost`, `127.0.0.1`) или файла внутри проекта | без вопроса |
| `open` любого другого хоста | вопрос; «разрешить на сессию» запоминает хост (`browser:host:имя-хоста`) |
| адрес, который пользователь сам ввёл в адресной строке | хост разрешён |
| `click`, `type`, `press` в режиме «только чтение» | запрещено, как и внешние хосты |
| навигация страницы на чужой хост (ссылка, редирект) | блокируется на уровне CDP (`Fetch`, ответ 204), в окне баннер «заблокировано» |

Текст страницы считается недоверенным (как вывод `web`/MCP): после чтения внешней страницы любая запись в файл или команда спрашивает подтверждение даже в режиме авто-правок. Исключение: страница, которая сама лежит внутри проекта (файл в `file://` корня проекта) не заражает сессию, иначе сценарий «открой, проверь, исправь» всё время упирался бы в вопросы. Это закреплено тестом в host (страница с `localhost` заражает, файл проекта нет).

## Предпросмотр

Файл в правой панели открывается кнопками «Код» / «Просмотр» (PDF сразу как просмотр):

| Тип | Просмотр |
|---|---|
| `.md` | разметка через `marked` + `DOMPurify` |
| `.csv`, `.tsv` | таблица (до 500 строк, шапка закреплена) |
| `.json` | дерево со сворачиванием, ошибка разбора показывается текстом |
| `.html` | статичный просмотр во фрейме без скриптов (`sandbox=""`): стили `link rel=stylesheet` и картинки из проекта подставляются, теги script вырезаются, потому что окно запрещает чужой код по CSP. «Открыть в браузере» запускает страницу целиком во встроенном браузере |
| `.pdf` | `pdf.js` (подгружается при первом открытии, воркер отдельным файлом), до 40 страниц на холст |

Обновляется при изменении файла (агентом или внешним редактором).

## Статистика проекта

Вкладка «Статистика». Всё считается и хранится локально: `.gemmacode/stats.db` (SQLite через встроенный `node:sqlite`, нужен Node 22.5+, в Electron 45 это Node 24; если недоступен, вкладка показывает код и git и пишет причину).

- Код: файлы, строки, языки (без `node_modules`, `.git`, сборок и бинарников; подсчёт обрывается на крупных деревьях и помечается «усечён»).
- Git: коммиты за 30 дней, добавлено/удалено, незакоммиченное.
- Агент: число ходов, токены на входе и на выходе, средняя скорость генерации (по токенам) с отметкой цели 60 ток/с, время до первого токена, доля инструментов без ошибок, таблица инструментов, строки `+`/`−` в правках агента по дням (30 дней), скорость по последним ходам, память процесса модели (только для своего `llama-server`, по `ps`).
- Графики в цвете акцента темы, у каждого есть табличный вид («Таблицей»), выгрузка CSV и JSON (`stats.export`).

## Проверка на Mac с настоящей моделью

Машина: MacBook Air M1 8 ГБ, Node 24, Chrome. Модель Gemma 4 E2B Q4_K_M и mmproj-F16 (unsloth), `llama-server` с флагами приложения (контекст 16K, KV q8_0, `-np 1`, `--jinja`, reasoning выключен). Сценарии гоняет `apps/desktop/scripts/m3-real.ts` (свежий проект на каждый прогон, режим авто-правок, подтверждения разрешаются автоматически).

Сборка и тесты на Mac: типизация чистая, тесты 177 из 177 (core 90, host 18, protocol 6, eval 55, cli 8), смоук Electron 11 из 11 (страницы браузера в настоящих окнах Electron на macOS, статистика на Node Electron), e2e окна 19 из 19 с Google Chrome.

Сценарии с настоящей моделью:

| Сценарий | Итог |
|---|---|
| A. «Исправь функцию sum в utils.js: она должна складывать» (фраза, на которой в M2 модель просила прислать файл) | 3 из 3, затем снова 3 из 3 |
| B. Гейт: «Открой страницу site/index.html в браузере, проверь её и исправь, если что-то не так» | итоговый прогон на финальном коде 3 из 3, до правки path см. ниже |
| C. «Открой site/index.html в браузере, посмотри приветствие и исправь опечатку» | 3 из 3 |
| edit30 (регрессия гейта M1, нужно 20) | 26 из 30, невалидных вызовов 0, прежде 26–28 в разных конфигурациях |

Типичная цепочка в B и C: `browser open` → `read_file` → `edit_file` (иногда ещё `browser reload` для проверки), 30–40 с на задачу, 20 ток/с, до первого токена около 6 с, `llama-server` около 2,4 ГБ.

Как шли отладка и правки:

1. Первый прогон: A 3 из 3, B и C по 0 из 3. Часть ходов завершилась за 0–5 с без вызова инструмента. Повторить это не удалось: к концу прогона каталог `~/.cache/huggingface` с моделью исчез с диска (причину установить не удалось, в коде приложения удаления нет), модель скачана заново в `~/Projects/models/gemma4-e2b/`. Это единственный нерасшифрованный сбой.
2. Прогоны с диагностикой: B 2 из 5 и 1 из 5. Почти все провалы имели одну причину: после `read_file` модель зовёт `edit_file` без аргумента `path` (три невалидных вызова подряд, обрыв хода `invalid_tool_calls`). Падения сервера в логе нет, памяти хватало (свободно 14–18% при браузере и модели).
3. Правки: подстановка прочитанного файла в `edit_file` без `path` (см. выше) и подсказка в описании `browser`. После них B 6 из 6, затем в итоговом прогоне 3 из 3.
4. Остаточная слабость: в сценарии A первый `edit_file` иногда ошибается (`old_string` не найден), модель перечитывает файл и повторяет. Ошибок инструментов 3 из 36 вызовов, все в A.

Не проверено: фото через встроенный браузер (`screenshot`), длинные сессии в окне с браузером, Windows и Linux с настоящей моделью.

## Ограничения M3

- Браузер агента: один профиль на окно, без сохранения cookie между запусками; загрузка файлов, диалоги `alert/confirm` и выпадающие списки select не поддерживаются.
- Снимок страницы не видит содержимого `iframe` и shadow DOM.
- Предпросмотр HTML статичный: страницы, которые рисуются скриптами, надо открывать в браузере.
- Видео-вложений нет (отменены).
- Память модели в статистике есть только для `llama-server`, запущенного самим приложением.
