# M2: окно GemmaCode

Всё, что в M1 было доступно в терминале, теперь есть в окне: чат с diff, файлы, терминал, фото и звук, откат сессии.

## Устройство

Три процесса Electron, у каждого одна роль.

| Процесс | Где | Что делает |
|---|---|---|
| Главный | `apps/desktop/src/main` | Создаёт окно, показывает системные диалоги, открывает корзину, пересылает сообщения. Файловой системы агента не касается |
| Сервис агента | `packages/host` (бандл `dist/host/host.cjs`) | Работает в utility-процессе: ядро из M1, сессии, права, файлы, терминалы, вложения, `llama-server` |
| Окно | `apps/desktop/src/renderer` | React, CodeMirror 6, xterm.js. Без Node, `sandbox: true`, связь только через `contextBridge` |

Протокол окна и сервиса описан в `packages/protocol`: запросы `{id, method, params}`, ответы `{id, result|error}`, события `{event, data}`. Сервис не знает про транспорт: в приложении это IPC через главный процесс, в проверках и для разработки веб-страницы это WebSocket (`packages/host/src/transports/ws.ts`). Поэтому окно целиком проверяется в браузере на настоящем ядре.

Все действия на хосте проходят через ядро и слой прав M1. Окно только показывает запрос и отправляет ответ пользователя.

## Что умеет окно

| Возможность | Как устроено |
|---|---|
| Чат и лента | Потоковый ответ, карточки инструментов, рассуждения, проверка loop. Лента строится из событий ядра одной функцией (`protocol/src/feed.ts`), она же восстанавливает ленту открытой сессии |
| Diff | Ядро считает diff до записи (`Tool.preview`) и после. Запрос подтверждения показывает, что изменится; в ленте остаётся diff сделанной правки |
| Подтверждения | Карточка с вариантами «Разрешить», «разрешить в сессии», «Отклонить». Режим прав переключается в строке состояния или командой `/mode` |
| Файлы | Дерево проекта с метками git (M, U) и точкой у файлов, которые менял агент; поиск по имени и по тексту; создание, переименование, корзина; правка в CodeMirror с сохранением по ⌘S; картинки и звук просматриваются встроенно |
| Изменения | Все файлы сессии с diff относительно состояния до первой правки |
| Терминал | Настоящий shell в корне проекта (`@lydell/node-pty` в сервисе, xterm.js в окне) |
| Фото | Уменьшаются в окне до 1024 по большей стороне и сохраняются в `.gemmacode/attachments/`. Модели уходит только картинка последнего сообщения с вложением |
| Звук | Раскодируется браузером, сводится в моно 16 кГц, режется на WAV по 30 с (до 4 фрагментов), уходит как `input_audio` |
| Текстовые файлы | До 6000 символов вставляются в сообщение, длиннее передаются ссылкой на путь (агент читает `read_file`) |
| Файл проекта в чат | Кнопка «В чат», перетаскивание из дерева, `@имя` в поле ввода |
| Слэш-команды | `/mode`, `/verify`, `/undo`, `/diff`, `/new`, `/context`; скиллы подбираются ядром, как в CLI |
| Откат | У каждого сообщения пользователя кнопка «Откатить к этому ходу»: файлы возвращаются из снимков, история обрезается до контрольной точки |
| Модель | Окно настроек: готовый сервер по адресу или файл `.gguf` с `mmproj`, размер контекста, режим прав. Поиск моделей в типичных каталогах |

Без `mmproj` фото и звук модель не получит: при отправке сервис отказывает с подсказкой указать файл в настройках.

## Откат

Контрольная точка записывается в сообщение пользователя (`checkpoint`). `session.rollback` делает две вещи: возвращает файлы из `SnapshotStore` до состояния перед этим ходом и обрезает историю сессии до сообщения, предшествующего ему. Ленту окно перестраивает из сохранённой сессии. Файлы, которые агент создал, удаляются, изменённые возвращаются.

## Проверки

```bash
npm test                                   # ядро (74, на Linux 70: тесты Seatbelt идут только на macOS), протокол (6), сервис (13), оценка
cd apps/desktop && npm run test:e2e        # окно в headless Chromium на настоящем сервисе (15 шагов)
cd apps/desktop && npm run build && ELECTRON_BIN=<electron> xvfb-run -a npm run test:smoke   # настоящее приложение (8 проверок)
```

`test:e2e` поднимает сервис, поддельный OpenAI-сервер с заранее заданными ответами (те же SSE-дельты, что у `llama-server`) и окно. Проверяет открытие проекта, подтверждение с diff, отказ, сжатие картинки до 1024, WAV 16 кГц, `/mode`, метки git и агента в дереве, правку в CodeMirror, поиск, вкладку изменений, терминал, настройки, откат, перезагрузку окна и отсутствие ошибок в консоли. Скриншоты в `apps/desktop/e2e-out`.

`test:smoke` запускает собранное приложение под Electron: окно с `file://`, utility-процесс, IPC, ход агента, терминал, штатное завершение.

Проверки с настоящей моделью (картинка, звук, скорость, память) на целевой машине описаны в `docs/M2-mac.md`.

## Запуск

```bash
npm install
cd apps/desktop
npm run build && npx electron .     # собранное приложение
npm run dev                         # режим разработки с горячей перезагрузкой окна
```

Первый запуск: «Открыть проект», затем в настройках указать модель (адрес запущенного `llama-server` или файл `.gguf` и `mmproj`). Конфиг общий с CLI: `~/.gemmacode/config.json`.

## Ограничения M2

- Сборка установщиков и подпись не делались (план: M5). Приложение запускается из исходников.
- Видео приложить нельзя: решено не делать (см. M3).
- Окно не следит за внешним редактором, пока файл не открыт во вкладке: дерево обновляется по событиям файловой системы, содержимое вкладки загружается заново при изменении, если нет несохранённых правок.
- Без песочницы ОС (Windows) каждая команда агента требует подтверждения, окно показывает это в баннере.
