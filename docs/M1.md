# M1: ядро агента и CLI

Статус на момент написания: код и тесты готовы, прогон набора оценки на целевой машине (MacBook Air M1 8 ГБ) ещё не сделан, поэтому цифр по модели здесь нет. Результаты прогона пишутся в `eval/results/` и в `docs/M1-eval.md`.

## Что входит

| Часть | Где | Что делает |
|---|---|---|
| Цикл агента | `packages/core/src/agent/loop.ts` | «модель предлагает вызов → валидация → права → выполнение → результат». До 2 повторов при невалидном вызове (3 подряд — остановка), защита от зацикливания, лимит шагов, отмена |
| Способ вызова инструментов | `agent/strategy.ts` | `native` (поле tools, `--jinja`) и `schema` (ответ ограничен JSON-схемой, невалидный вызов невозможен) |
| Инструменты | `tools/` | `read_file`, `list_dir`, `glob`, `grep`, `write_file`, `edit_file`, `shell`, `skill`, `todo`, `host_app`. Наборы `read` / `edit` / `full` |
| Права | `permissions/` | Режимы `read-only`, `ask`, `auto-edit`, `full`; запретный список (`.env`, ключи, `~/.ssh`, хранилища браузеров) действует во всех режимах; метка «недоверенные данные» требует подтверждения для записей и команд |
| Песочница | `sandbox/` | macOS Seatbelt (запись только в проект и tmp, сеть выключена, секреты нечитаемы), Linux bubblewrap; без песочницы (Windows) каждая команда требует подтверждения |
| Снимки и откат | `snapshot/` | Оригинал файла сохраняется перед первой правкой в ходе; `/undo` возвращает файлы, `/diff` показывает изменения |
| Скиллы | `skills/` | SKILL.md в `~/.gemmacode/skills`, `.gemmacode/skills`, а также `.claude/skills`, `.agents/skills`. Подключение: инструмент `skill`, команда `/имя`, подбор ядром по тексту запроса |
| MCP | `mcp/manager.ts` | stdio и HTTP; не более 8 инструментов от сервера; результаты помечаются недоверенными; вызов всегда с подтверждением |
| Контекст | `context/` | Обрезка вывода инструментов (начало и конец), заглушки вместо старых результатов, детерминированная сводка старых шагов; срабатывает при 72% контекста |
| Режим loop | `agent/runner.ts` | После хода запускается команда проверки; если она падает, вывод возвращается агенту. Останов: успех, лимит попыток, нет прогресса |
| Само-ревью | `agent/review.ts` | Модель в чистом контексте проверяет diff своих правок; ответ по JSON-схеме; замечания без цитаты из diff и низкой важности отбрасываются |
| CLI | `packages/cli` | Интерактивный режим и `-p`; подтверждения, слэш-команды, `--json`, `--resume` |
| Набор оценки | `eval/` | 30 задач на правку и 20 на генерацию кода, у каждой эталонное решение; самопроверка набора |

## Запуск

```bash
npm install
# есть запущенный llama-server:
npm run gemmacode -- --server-url http://127.0.0.1:8080 --mode auto-edit
# или GemmaCode сам запускает llama-server:
npm run gemmacode -- --model-file ~/models/gemma-4-E2B-it-Q4_K_M.gguf
# разовая задача с повтором до зелёных тестов и ревью:
npm run gemmacode -- -p "почини тесты" --mode auto-edit --verify "npm test" --review
```

Конфиг: `~/.gemmacode/config.json` и `.gemmacode/config.json` проекта (режим, наборы инструментов, правила `permissions.allow/deny` вида `shell(npm test*)`, `mcpServers`, `server`).

## Набор оценки

```bash
npm run test:eval        # самопроверка набора: без решения проверка падает, с эталоном проходит; конвейер на «идеальной модели»
npm run eval -- --server-url http://127.0.0.1:8080 --suite edit30                  # гейт M1: 20 из 30
npm run eval -- --server-url ... --suite all --tool-mode schema                    # режим schema
npm run eval -- --server-url ... --suite all --loop --review --label loop-review   # loop и само-ревью
```

Проверка выполняется скрытыми тестами: они перезаписываются перед запуском, поэтому «починить» тест нельзя. В режиме `--loop` агент видит только то, что мог бы запустить пользователь: видимые тесты (13 задач) либо проверку синтаксиса.

## Решения и упрощения M1

- Сессии хранятся построчным JSON (`.gemmacode/sessions`), а не в SQLite: проще чинить и читать; перенос в M2 вместе с интерфейсом.
- Откат охватывает файловые инструменты. Побочные эффекты `shell` (например, `rm`) снимок не видит; от них защищает песочница и подтверждение.
- `patch` (unified diff) не сделан: для E2B надёжнее `edit_file` с нечётким сопоставлением по отступам.
- Скиллы: в M0 модель не вызывала инструмент `skill` по списку в промпте (0 из 4). Поэтому по умолчанию (`skillRouting: auto`) тело скилла подставляет ядро: по `/имя` или по совпадению запроса с описанием. Режим `model` (только инструмент) оставлен для сравнения.
- Само-ревью идёт в свежем контексте, поэтому кэш префикса движка сбрасывается и следующий ход префиллит историю заново. Альтернатива (ревью в общем контексте) дешевле, но менее строгая.
- MCP-серверы запускаются без песочницы: они заданы пользователем явно. Песочница для них — отдельная задача.
- `host_app` (open, AppleScript, PowerShell): всегда с подтверждением, песочница к GUI не применима.
- Windows: песочницы нет, каждая команда с подтверждением (как в плане).
