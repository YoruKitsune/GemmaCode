## Замеры M5 (MacBook Air M1 8 ГБ, E2B Q4_K_M)

Условие: машина занята (swap 4,2 из 5 ГБ во время прогона, RSS сервера 1,5 ГБ), поэтому скорости, скорее всего, занижены; на свободной памяти стоит перемерить.

### Стоимость сжатия контекста

`node bench/compaction-cost.mjs --model-file … --bin … --lines 24`: история агента около 11K токенов, `llama-server` с флагами приложения (`ngram-simple`, ctx 16384). Время — это prefill, то есть ожидание перед первым токеном.

| Шаг | Взято из кэша | Дозалито | Время | Скорость prefill |
|---|---|---|---|---|
| первый запрос, кэша нет | 0 | 11 371 | 62,6 с | 182 ток/с |
| обычный ход (+1 шаг) | 11 371 | 1 033 | 8,5 с | 121 ток/с |
| elide: 6 старых результатов заменены заглушками | 675 | 6 322 | 28,0 с | 226 ток/с |
| обычный ход после elide | 6 997 | 1 034 | 6,3 с | 163 ток/с |
| summary: сводка и хвост из 8 сообщений | 675 | 4 179 | 16,8 с | 249 ток/с |

Вывод: сжатие сбрасывает кэш до системного префикса (675 токенов), и ход после него ждёт 17–28 с, один раз. До следующего сжатия проходит около четверти контекста (порог 72%, цель 50%), то есть несколько ходов. Изменение порогов выигрыша почти не даёт: цена одного сжатия определяется размером истории после него, а не частотой. Код сжатия оставлен как есть. Строка «обычный ход после summary» в стенде показывает, что кэш не восстановился (675 из 4916), но это артефакт стенда: он пересобирает текст сводки каждый шаг; в приложении сводка записывается в историю один раз и дальше стоит неизменной, так что префикс стабилен. Замера «в приложении» на длинной сессии нет.

Холодный первый шаг сессии (62 с на 11K токенов, 4–6 с на типичном коротком префиксе) остаётся главной причиной ожидания; вынос дерева проекта из префикса не делался.

### MTP-черновик (draft-mtp)

В M4 было записано, что `draft-mtp` невозможен, потому что в основном GGUF нет MTP-слоёв. Это неполно: в репозитории E2B есть отдельный файл `mtp-gemma-4-E2B-it.gguf` (97 817 664 байт, sha256 `9eba8199…1919`), и в `llama-server` b11669 он подключается так: `--spec-type draft-mtp --spec-draft-model ФАЙЛ [--spec-draft-n-max 3]`. Файл загружается без ошибок. Результат на тех же флагах приложения:

| | chat, ток/с | edit, ток/с | принято черновиков | RSS сервера |
|---|---|---|---|---|
| `ngram-simple` (по умолчанию) | 25,0 / 25,3 / 25,8 | 117 / 117 / 117 | 81% (1439 из 1772) | 1474 МБ |
| `draft-mtp` | 23,5 / 23,0 / 23,0 | 35 / 33 / 39 | 98% (1118 из 1140), в среднем 3,9 токена | 1545 МБ |

MTP принимает почти все черновики, но на chat медленнее, а на edit втрое медленнее синтетического копирования, которое ловит `ngram-simple`. Выигрыша нет, по умолчанию остаётся `ngram-simple`. (Цифры edit здесь синтетические, как в M4: на реальных ходах агента выигрыш `ngram-simple` 1,1–1,8 раза.) Реальные ходы агента с MTP не гоняли: на синтетике он проигрывает, остановились по правилу «мало выигрыша — не тратим время».

## Linux и Windows: что выяснилось

- **Linux** собирается в контейнере и проходит проверку; найдены и исправлены три ошибки упаковки: `executableName` с символом `@` из имени пакета, отсутствие `homepage` для deb, жёстко прописанный `electronDist`.
- **fetch-llama.mjs** не читал zip на Linux (GNU tar не умеет zip, bsdtar есть только на macOS и Windows): теперь на Linux zip распаковывается `unzip`.
- **Windows нельзя собрать кросс-сборкой с Linux:** NSIS требует wine для деинсталлятора, а в пакет не попадает нативный модуль терминала `node-pty-win32-x64` (electron-builder берёт опциональные зависимости по платформе хозяина). Поэтому установщик Windows собирает только родной раннер (`windows-2022` в релизном workflow). Распаковка архива `llama.cpp` для Windows (zip, SHA-256) и сборка каталога `win-unpacked` проверены в контейнере: `llama-server.exe` и DLL на месте.
- Подпись и значок самого `GemmaCode.exe` на Windows: `signAndEditExecutable: false`, значок в exe не вшивается (нужен wine или подпись), установщик и окно иконку имеют.

## Релиз

Тег `vX.Y.Z` запускает `.github/workflows/release.yml`: сборка на `macos-14`, `ubuntu-22.04`, `windows-2022`, затем `SHA256SUMS.txt` и предварительный релиз со всеми файлами. Сборки не подписаны (README описывает обход Gatekeeper и SmartScreen). Релизы собираются только в CI, чтобы нативные модули и `llama-server` были своей платформы; локальный dmg с Mac нужен для проверки.

## Что не сделано

- Подпись и нотаризация macOS (нужен сертификат Apple Developer), подпись Windows, автообновление. README и PRIVACY прямо говорят об этом.
- Сборка Windows и CI на Windows и macOS проверяются только на GitHub Actions; результаты первого запуска см. в CHANGELOG и релизе.
- Скорость и качество вызовов инструментов E4B и 12B; перемер E2B на свободной памяти.
- Цель 60 ток/с остаётся не достигнутой (решение M4: реалистично 25–40 ток/с на правках).
- Скиллы по списку модель по-прежнему не вызывает (0 из 4 в M0), они идут через маршрутизацию ядром; видео-вложения отменены.
- Песочница на Windows слабее, чем на macOS и Linux; по умолчанию там подтверждается каждая команда.
