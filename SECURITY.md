# Безопасность

## Как сообщить об уязвимости

Откройте приватное сообщение через раздел **Security → Report a vulnerability** репозитория https://github.com/YoruKitsune/GemmaCode (GitHub Security Advisories). Если он недоступен, создайте обычный issue без технических подробностей, и мы свяжемся с вами. Публичные issue с описанием эксплойта до исправления просим не создавать.

В отчёте полезно: версия приложения, система, шаги воспроизведения, что удалось сделать (например, прочитать файл вне проекта или выполнить команду без подтверждения).

## Что считается уязвимостью

- Обход слоя прав: запись или команда без подтверждения в режиме «спрашивать», чтение запретного списка (`.env`, `~/.ssh`, токены).
- Выход из песочницы ОС (Seatbelt, bubblewrap и Landlock) или сети у команд, где она должна быть выключена.
- Prompt injection через страницу или файл, который приводит к действию без подтверждения (данные из браузера и внешних файлов помечаются недоверенными, любая запись или команда после них требует подтверждения).
- Подмена модели или `llama-server` при загрузке (проверка SHA-256 обходится).
- Выполнение кода из HTML-предпросмотра или Markdown за пределами изолированного iframe.

Что известно и описано, а не уязвимость: песочница на Windows слабее, чем на macOS и Linux, поэтому там по умолчанию подтверждается каждая команда; сборки не подписаны (см. README).

## Поддерживаемые версии

Пока проект в бете, исправления выходят только в последней версии.
